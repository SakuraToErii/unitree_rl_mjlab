# 比 OmniTrack 更好：从你已经看到的失败出发

上一篇 [`ghost_paper_thesis.md`](ghost_paper_thesis.md) 按公开仓库写，把「用 Ghost npz 训 Tracking」当成还没做。你这边已经做完了：洗过的数据训得更快、跟得更稳。那部分和 OmniTrack 的主结论对齐，本身不再是新故事。

真正新的是你后面三句话：

1. 动捕很差时，Ghost npz 会 **发明小碎步**。
2. 有些高难动作 **用生数据能训出来，用 Ghost 反而训不出**。
3. 你已经在用 **切片单独攻关**（仓库里的 Assault + `chain_motion` 拼接）。

OmniTrack 把物理化写成「几乎无损的滤波器」：穿地/浮空到 0，MPJPE 只涨 16–21 mm，下游全面更好。你的现象说明它不是滤波器，是一个 **会改动作语义的投影器**：该站的时候可能改成走，该飞的时候可能改成蹭。论文要写的不是「我们也洗」，而是 **「洗会破坏什么、何时不该整段替换、怎么自动决定」**。

白话背景仍看 [`ghost_for_beginners.md`](ghost_for_beginners.md)。

---

## 1. 小碎步：不是随机噪声，是奖励在逼它走路

Ghost 训练时（`src/tasks/ghost/tracking_env_cfg.py`）有三条叠在一起：

- 根的 **世界系 XY** 跟踪很重（权重 1.0）。动捕骨盆在地上滑或漂时，参考仍要求「骨盆沿着那条平面轨迹走」。
- 脚允许随时撑地。多踩一步 **不扣分**（undesired contact 只罚头、膝、屁股，不罚多出来的脚步）。
- 身体形状奖励是 **相对骨盆** 的。脚在下面碎步、上半身姿态还能对上，形状分仍然高。

于是开挂策略的捷径是：脚放下（别漂）、骨盆去追那条可能是滑的 XY（别丢根轨迹分）、用一串小步把「漂着的重心」改成「走着的重心」。看起来像物理对了，语义已经从「站/滑/飞」变成「走」。

动捕越差（漂、滑、重心和脚对不上），这条捷径越划算。所以碎步集中出现在坏动捕上，不是偶然。

OmniTrack 的 PMG 也有根位置奖励，脚也可以接触。他们多半也有碎步，只是没当指标报。你要比他们好，第一步是 **把碎步测出来**，不要只报穿地和浮空。

建议加进 `quality_report` 的量（相对 **生数据**，不是只看 Ghost 自己）：

- 脚步次数 / 步频，相对生数据踝关节高度估出来的着地次数；
- Ghost 多出来的着地（invented steps）；
- 生数据里双脚都离地的阶段，Ghost 是否仍在踩地（飞相被踩死）；
- 平均步长变小、步频变高（碎步的定量定义）。

没有这张表，审稿人会说你只是调奖励。有了这张表，碎步就从「观感不好」变成论文现象。

## 2. 高难动作生数据更好训：Ghost 可能把「能飞」洗成「能站」

侧空翻、大跳、猛转这类动作，生数据常常几何上假（穿地、飞的时候脚还在地里），但 **能量和时序是真的**：起跳瞬间的角速度、手臂预摆、腾空时间。Tracking 跟着这条「假但猛」的轨，有时能摸到正确的飞相。

Ghost 的目标是整段可积、别摔、XY 还要对。对高难片段，最容易的可行解往往是：

- 提前放下脚（碎步或蹭跳）；
- 把角动量泄掉，换成低头弯膝站稳；
- 飞相插入接触。

洗出来的 npz **更可行，但不再是那个技能**。你拿它训 Tracking，等于让歌手去学一首被改成慢歌的谱，当然不如跟原谱（哪怕原谱有假音）。

这和 OmniTrack 的平均结论不矛盾：他们在 LAFAN1 全体上物理参考更好；你的反例是 **技能被投影改掉的那几条**。把反例写成论文是合理的，标题可以是：物理化不是免费午餐。

切片攻关为什么有效：你把「起跳 1 秒」单独拿出来，用 Assault 放宽早停、缩短 episode，强迫网络先学会这一下，而不是让 Ghost 先把这一下改成碎步再交给 Tracking。仓库里已经有 `TK3-Ghost-Tracking-Assault` 和 `chain_motion.fill_coverage_plan`（专家片段填洞、默认策略盖其余）。你现在是手工切；自动化就是方法。

## 3. 比 OmniTrack 更好：不要「洗得更干净」，要「有选择地洗」

OmniTrack 的默认合同是：

```text
生数据 ──整段替换──► Ghost 状态（关节+根+接触）──► Tracking
```

你的合同应该改成：

```text
生数据 ──诊断──► 每一段选择一种用法 ──► Tracking
              ├─ 整段用 Ghost（走路、站、坏得不致命的日常）
              ├─ 姿态用生数据，接触/高度用 Ghost（要风格、要防漂）
              ├─ 生数据 + 切片 Assault（高难、Ghost 会碎步或泄能）
              └─ 拒收 / 人工（投影只能发明步态才能活）
```

这叫 **选择性物理化**，不是更好的 OmniTrack。主张一句话：

> 物理运动生成器会幻觉步态、会毁掉高动态技能；正确用法不是总用它替换参考，而是按段决定替换、融合还是保留生数据，并把切片攻关从手工变成诊断驱动的流水线。

下面三层都可以做。建议按这个顺序，每一层单独就能写实验。

### 3.1 先测（没有测，后面都像调参）

对每个 clip 同时存生数据和 Ghost npz，报：

| 指标 | 用来抓住 |
|---|---|
| 穿地 / 悬空 / 力矩（你已有） | OmniTrack 同款可行性 |
| 额外脚步、步频比、飞相踩地 | 碎步 |
| 相对生数据的根高、动能、角动量 | 高难泄能 |
| Tracking 成功率：生 vs Ghost vs 融合 | 「有时生数据更好」的主表 |

把 clip 分成三类：Ghost 稳赢、打平、Ghost 更差。OmniTrack 只讲了第一类的平均。

### 3.2 改 Ghost 本身：少发明步，保留飞相

针对碎步，改的是 **Stage I 目标**，不是再加一点平滑：

1. **非对称接触：允许多少踩，罚多种踩。**  
   用踝高度/速度从生数据估一个粗糙着地（不必完美）。Ghost 少一次着地可以（漂着的假接触本就该删），多一次着地重罚。现在「脚随时可以踩」等于鼓励碎步。

2. **坏支撑时减弱根 XY。**  
   生数据在漂/滑时，XY 轨迹本身不可信。你现在 XY 权重 1.0、Z 只有 0.25，正好是「追假重心 → 碎步」。漂的阶段把 XY 降下去，让策略改高度和脚，而不是在平面上补步。

3. **飞相锁。**  
   生数据双脚都明显高于地面（或动能高于阈值）时，Ghost 再踩地就终止或重罚。逼它要么跳出这一下，要么失败交给 Assault，禁止用碎步混过去。

残差 `q_ref` 对碎步是加分项（修正更局部），但 **单靠残差压不住碎步**；碎步是接触日程问题，不是关节零点问题。

### 3.3 改 Stage II 怎么用 npz：融合，不要整段替换

这是比「Ghost 训得更好」更新的用法，也直接解释你的高难反例。

**融合 A — 姿态跟生，接触跟 Ghost（优先做）**

Tracking 的关节/身体目标仍用动捕（风格、预摆、腾空时序），奖励里的 desired-contact、根高度用 Ghost。OmniTrack 是状态和接触一起换成 rollout；你拆开：Ghost 当 **物理老师**，不当 **动作作者**。

高难动作往往就能训：飞的轨迹还在，只是告诉策略「这段不该踩地 / 落地后该踩」。

**融合 B — 按帧混合**

每帧一个权 \(w_t\)：Ghost 可行性高且没有额外脚步时信 Ghost，否则信生数据。\(w_t\) 可从现有 `quality_report` 的逐帧量来。

**融合 C — 按段路由（把你的手工切片自动化）**

用 Ghost 训练时的失败 bin、额外脚步、动能跌落，自动切出「该 Assault 的窗口」，默认段用 generalist Ghost，难段用生数据 Assault，再用已有 `fill_coverage_plan` 拼回一条 npz。你已经在走这条路，差的是 **诊断切点**，不是拼接器。

## 4. 更多用法（比「再洗一个数据集」好讲）

这些都建立在「Ghost 是带失败模式的投影器」上，而不是又一个跟踪器。

1. **动捕质检。** 碎步分数、飞相踩地、泄能，用来给动捕/重定向打分：哪段该重录、哪段 IK 坏了。产品是报告，不是策略。比 OmniTrack 多一个「诊断工具」叙事。
2. **自动切片工厂。** 失败 bin → Assault 任务 → 拼回。你现在的手工攻关变成论文里的算法。系统贡献，RA-L / ICRA 很吃。
3. **遥操作安全阀。** 在线若 Ghost 只能靠碎步跟上操作者，说明指令不可行：该减速、缩小步态、或拒绝，而不是在真机上跟着碎步。OmniTrack 把 PMG 当滤镜直接执行；你可以当 **可行性检测**。
4. **只买接触、不买动作。** 融合 A 本身就是用法：物理参考库可以只存 `contact_mask` 和根高度，动作库仍用大量脏动捕。数据更便宜。
5. **可编辑物理化。** 用户说「跳保留、只修落地」。飞相锁 + 分段路由就是编辑器。比黑盒整段替换更像工具。
6. **跨机器人。** 同一段生数据，TK3 和 G1 各洗一次；碎步/泄能当 embodiment gap 的度量。比「我们也能在 TK3 上 OmniTrack」干净。

不要把用法写成十个 demo。论文里 **一个主方法（选择性物理化）+ 两到三个用法（质检、自动切片、融合训练）** 就够。

## 5. 投稿时怎么说「比 OmniTrack 好」

能写进 abstract 的对比（实验成立的前提下）：

- 同样洗参考，我们 **额外脚步更少**，飞相不被踩死；
- 在他们会平均赢的日常/舞蹈上，我们不差；
- 在高难子集上，**纯 Ghost 替换会掉成功率，融合或路由能救回来**（这是他们没报的）；
- 切片攻关从人工变成由碎步/泄能/失败 bin 触发。

不要写：

- 首次物理化参考；
- 首次残差；
- 我们穿地更少所以全面更好（他们已经 0% 穿地）；
- 高难我们也能纯 Ghost 训出来——如果你的观察还在，硬吹会和自己的数据打架。诚实写反例更有力。

venue 仍然是：主攻 RA-L / ICRA；真机上做出「融合救了高难 + 碎步可测」再谈 TRO。Science Robotics 还是别当目标。

## 6. 建议你实际动手的顺序

不要并行开十条线。按你已经有的痛来：

1. **给现有 Ghost npz 打碎步/泄能标签**（相对生数据）。先确认「动捕差 → 碎步」「高难训不出 → 飞相被踩或动能掉了」能在表上看到。一周内就能知道论文现象实不实。
2. **Stage II 融合 A**：同一批 Tracking 配置，三种参考打成功率：生、Ghost 整段、生姿态+Ghost 接触。这张表直接回答「怎么比 OmniTrack 更多用法」。
3. **Stage I 飞相锁 + 少罚多种踩。** 看碎步指标掉多少、高难有没有被少毁掉。
4. **失败 bin 自动切 Assault**，接到现有 `chain_motion`。把你已经在做的手工流程写成方法。

残差 `q_ref` 可以夹在第 3 步当消融，不要当 title。

若第 1 步发现碎步和「生数据更好训」对不上（比如高难失败其实是切片太短、PD 不够、力矩饱和），再回来改主张，不要先写死「幻觉步态」四个字。现象以你的表为准。
