# Ghost 到底在干什么：给刚接触人形运控的说明

上一篇 [`ghost_paper_thesis.md`](ghost_paper_thesis.md) 用的是投稿口径，术语密。本文用仓库里的天工人形 3（TK3）把同一件事讲开：人的动作怎么变成机器人指令、中间会翻车在哪、Ghost 补的是哪一刀、为什么「补这一刀」现在不太够发一区。

读完你应该能自己讲清四句话：

1. 人形「模仿人类动作」不是把关节角度复制过去就完了。
2. 复制过去的动作经常在物理上不成立（脚插进地、人飘在空中、电机扭不动）。
3. Ghost 是在仿真里先把这段动作「洗」成机器人做得到的版本，再拿去训练真正能上机的控制器。
4. 这件事 2026 年已经有人做成了系统（OmniTrack）；我们还能写的，是洗的方式，不是「我们也洗了」。

---

## 1. 先建立一张总图

把整条链路想成「教机器人跳一段人类录下来的舞」：

```text
人跳了一段舞
    ↓ 动捕 / 视频重建
一串人体骨架角度（SMPL 之类）
    ↓ 重定向 retarget（按比例把人的骨架套到 TK3 身上）
一段「看起来像 TK3 在跳」的关节轨迹  ← 这就是参考动作 reference
    ↓ 强化学习策略每 10ms 输出关节目标
电机 PD 去追这些目标
    ↓
仿真里的机器人，或真机
```

仓库里其实有两套任务，对应这条链的后半段：

| 任务 | 代码 | 角色 |
|---|---|---|
| **Tracking** | `src/tasks/tracking/` | 真正要部署的模仿控制器。观测接近真机：关节角、角速度、IMU、上一步动作。训练时会故意把摩擦、质量、延迟随机化，逼策略别过拟合干净仿真。 |
| **Ghost** | `src/tasks/ghost/` | **不部署**。观测是开挂的（知道全局位置、接触力、未来几帧参考）。它的产品不是「会跳舞的策略」，而是一段洗过的 `*_physical.npz`，给 Tracking 当新的参考。 |

`PROTOTYPE.md` 里 Ghost 自己的定位就一句话：特权 PPO 把一段吵闹的 100 Hz 动作，变成力矩有限、不严重穿地、不悬空漂着、还大致沿着原轨迹的 MuJoCo 回放。

## 2. 为什么「看着像」不等于「做得到」

人和 TK3 不是同一个身体：腿长、脚掌形状、腰的自由度、电机最大扭矩都不一样。重定向通常只保证 **几何上能套上**（IK、缩放、对齐关键点），不管 **动力学上站不站得住**。

于是参考里会出现三类很具体的假动作。你可以在可视化里对着「幽灵参考」（半透明那个）看。

### 2.1 穿地（penetration）

参考里脚的高度算低了，脚掌有几毫米埋进地板。人的皮肤能压、动捕也有噪声；机器人脚是硬的。仿真器为了「脚在地里」会挤出很大的接触力，机器人就被弹起来，或者策略为了贴参考硬往下踩。

Ghost 的质量报告把「任意部位往地里超过 5 mm」的帧算作深穿地。这不是审美问题，是接触力会炸。

### 2.2 浮空 / 假支撑（floating）

反方向：该着地时脚还在地面上方，但参考的骨盆高度像站稳了一样。物理上这叫「没人托着你，你却不掉下来」。OmniTrack 用「骨盆高于 0.8 m 持续 1 秒」当浮空，对 G1 站立还凑合，跳跃会被误伤、蹲着漂会漏掉。Ghost 用更物理的定义：地上没有任何允许接触，竖直速度几乎为零，同时竖直加速度还不像自由落体——等于仿真在吊着机器人。

### 2.3 力矩不够 / 关节到硬限位

人能深蹲、能猛甩手臂。TK3 关节有角度上限，电机有牛顿·米上限。参考要你 0.05 秒内把膝盖转到某个角，电机给不出那么大扭矩，真实轨迹必然落后。策略如果死追参考，就会饱和、震荡、摔倒。

**一句话：** 参考是「希望机器人长这样」，物理是「电机和地面允许你长这样」。两者打架时，只训练一个「跟着参考走」的网络，它不知道该信哪边。

## 3. 跟踪策略实际在优化什么

强化学习（这里是 PPO）可以先当成：很多个并行仿真里的机器人，每一步做一个小决定，根据打分调网络。

每一步策略输出的不是电流，而是 **29 个关节的目标角度**。下面一层是 PD：

```text
力矩 ≈ Kp × (目标角 − 当前角) − Kd × 当前角速度
```

`Kp` 像弹簧刚度，`Kd` 像阻尼。目标角离当前角越远，力矩越大，但会被电机上限截断。

打分（奖励）大致是：

- 根（骨盆）是不是跟着参考走；
- 大腿、小腿、手这些关键身体是不是形状对；
- 动作别抖；
- 别撞到不该撞的地方（头、膝盖跪地——除非你允许手撑）。

早停：歪太远、出现 NaN、有时碰到硬限位，这一局结束，换一段再练。

**Tracking 为什么难：** 真机没有「我现在世界坐标是多少、脚底力是多少、参考未来 200 ms 长什么样」这些信息。它只有关节编码器、IMU、上一次指令。参考里如果有穿地和浮空，这个半瞎的策略会把假动作也当成必须跟上的目标——该抬脚时往下踩，该落地时还在空中比划。

这就是上一篇说的 **「跟踪精度 vs 平衡稳定互相拆台」**：

- 你把「跟着参考」的分加重 → 它追假动作，摔。
- 你把「别摔」的分加重 → 它保守站着，舞没了。
- 不同动作的最佳折中还不一样（走路和侧空翻不是同一套权重）。

部分可观的部署策略，没有足够信息判断「这段参考是假的，不该跟」。

## 4. Ghost / OmniTrack 的核心想法：先洗参考，再学跟踪

把一件事拆成两个工种。

### 第一阶段（Ghost，也叫 PMG：Physical Motion Generator）

给策略开挂：

- 精确的仿真状态（包括全局位置、速度、接触）；
- 参考的现在和未来几帧（Ghost 在 100 Hz 上看现在、50 ms、100 ms）；
- **不** 随机化摩擦/质量（要洗得准，不要洗出一堆随机风格）；
- 只对参考本身加一点点噪声，免得只会复读一条轨迹；
- 力矩上限仍然按真机，洗出来的动作才有资格以后上机。

然后在仿真里整段播完，把 **机器人实际走出的状态** 存成新参考：关节、身体位姿、速度、哪几帧脚/手着地。这就是 `rollout_ghost.py` 写出的 `*_physical.npz`。

因为它是仿真器里一步步积出来的，这段新参考 **按定义** 满足这套仿真的物理：不会无故悬空、穿地会被接触力顶回来、力矩超了就转不到。风格会变差一点（关节误差变大一点），那是为了换「做得到」。

OmniTrack 报告过数量级：洗完以后穿地/浮空百分比掉到 0，相对原始动作的关节误差大约增加 16–21 mm。这是「洗」的代价，不是洗失败。

### 第二阶段（Tracking）

用洗过的参考，训练 **不能开挂** 的策略。现在参考本身站得住，策略的任务简化成：在噪声、延迟、摩擦不准、被人推一把时，仍然跟上一段「本来就做得到」的舞。

仓库现状：**第二阶段还没接到 Ghost 的输出上。** `src/tasks/tracking/` 仍在跟原始重定向动作。Ghost 洗完如果不用来训 Tracking，对论文来说只是做了数据清洗。

可以用两个比喻：

- **修图：** Ghost 是先把过曝/裁切修掉，Tracking 是在修过的图上做风格迁移。你不能又要修图、又要在原片噪声里学风格。
- **导航：** 原始参考是一条穿墙的 GPS 轨迹。Ghost 是先把路线拽回路上，Tracking 是闭着眼睛按路走（只有车内仪表）。

## 5. 「残差」是什么，为什么原型要改它

策略输出目标角，有三种常见写法。差在 **零点是谁**。

### 5.1 绕默认站姿（仓库 Ghost main 现在这样）

```text
目标角 = 站直时的默认角 q0 + 0.25 × 网络输出
```

网络必须自己「唱整首歌」：先学会大概长得像参考，再学会为了物理往旁边偏。容量花在重写动作上。

### 5.2 绕参考（原型 `ghost-qref-residual`）

```text
目标角 = 当前参考角 q_ref + 0.25 × 限幅后的网络输出
```

网络输出的是 **修正量**：参考已经 80 分，你只负责把穿地的脚抬 2 cm、把扭矩不够的膝少屈一点。这叫 **残差 residual**。

生活类比：修一篇稿。绝对动作是「不看原稿自己重写」；残差是「在原稿上改错别字和事实错误」。洗参考本来就是改错，不是创作。

### 5.3 为什么这还不够当论文卖点

2025–2026 已经有人把残差用在：

- 部署跟踪器上（RobotDancing：真机跳舞，目标 = 参考 + 修正）；
- 有界残差模仿（I-CTRL：不许离参考太远）；
- 真机和仿真不一致时补一刀（ASAP：残差补的是仿真器，不是动作本身）。

更早的图形学工作 SuperTrack（2021）就在参考附近加 PD 偏置。还有一篇 PHC 说了反话：**参考很脏的时候，残差会把你绑在脏轨迹上**，不如让网络自己出绝对目标。

所以原型改 `q_ref` 残差是对的工程直觉，但投稿时必须证明两件事：

1. 洗参考这个工种上，残差确实比绕 `q0` 更好（穿地更少、风格丢得更少）；
2. 参考很脏时，残差不会像 PHC 说的那样更差（否则审稿人会引用 PHC 把你打回来）。

这就是上一篇说「打开 `q0` / `q_ref` 双入口做消融」的原因：论文靠对比，不靠感觉。

## 6. 那些「运控难点」用场景说一遍

上一篇列了五条。下面每条都是：现场会发生什么、现有方法卡在哪、Ghost 如果要认领必须多做什么。

### 6.1 跟踪和稳定打架

**现场：** 参考里脚埋进地 1 cm。部署策略为了拿跟踪分往下踩，接触力把人弹飞；你把接触惩罚加大，它又不敢落地，走成高抬腿。

**已有答案：** OmniTrack 说：别让部署策略判断真假，先在开挂仿真里洗掉假动作。

**还空着的：** OmniTrack 训练时穿地仍是 **扣分**，不是 **禁止**。策略仍可能在穿地轨迹上刷跟踪分，只在最后归档时被 `quality_report` 扔掉。论文级做法是训练中途就不让这种局算成功：穿深、悬空、力矩越限直接失败或用约束优化（像「红灯不能闯」，不是「闯红灯扣分但总分还能高」）。

### 6.2 长时程误差越积越大

**现场：** 一段 10 秒的舞，前 2 秒还行，第 8 秒脚已经偏了 5 cm，后面全乱。绝对动作每步都在「重新发明」姿势，小偏差会积分。

**已有答案：** 部署端残差（RobotDancing）让网络只修差异。

**Ghost 能不一样的地方：** 把残差用在 **洗参考的人** 身上，让第二阶段拿到的就是不漂的谱。部署策略甚至可以继续用简单的绕默认站姿——论文要证明的是「谱洗干净了，后面更好学」，不是再发一篇部署残差。

### 6.3 手、膝、脚谁该撑地，从人身上抄不来

**现场：** 人爬起来会用手撑地。TK3 没有人的手掌，接触点在 `left_tcp_link` / 手腕外壳。人的动捕里「掌心着地」套到机器人上，可能是手悬空 3 cm，或手腕插进地板。

Ghost 已经把脚底和 TCP/手腕算成 **允许接触**，膝盖、头、屁股碰到地会扣分。这叫用手当 **支撑**（loco-support），还不是搬箱子那种带物体操作。

**已有答案：** 有人用几何网格保持「手靠近箱子」；有人用很慢的轨迹优化补上缺失接触；有一篇 DSMS 在可微仿真里 **自己长出** 爬行时手肘膝盖的接触，并且上了真机。所以不能写「我们第一次让机器人用手撑地」。

**还空着的：** 对着 **乱七八糟的野动捕**（没有人标哪一帧该撑），**接近实时** 地决定该用哪只手/脚，而不是算一分钟才能修一秒动作。仓库里如果只有平地走和舞，允许 TCP 接触等于没演示这条。

### 6.4 在线遥操作：人还在动，你不能回放整段

**现场：** 人穿动捕服或戴 VR，动作源源不断进来，带着抖动、丢帧、延迟。离线洗参考是「整首歌先修完再唱」。直播必须 **当前这一拍** 就给出做得到的关节目标。

OmniTrack 的做法是：旁边再跑一台仿真机器人当滤镜，洗完再送给真机策略。他们演示了管线，几乎没报：滤镜慢了多少毫秒、只能看未来 50 ms 还是 200 ms、人突然停住时会不会还在追过时的参考。

残差很适合当 **因果滤镜**：这一帧参考来了，只输出有界修正，不必在仿真里把未来 10 秒演完。这是冲更高档论文的加码，前提是真机遥操作 + 延迟扫描。没有真机就先别认领。

### 6.5 「物理一致」到底对哪套物理

**现场：** 仿真地板偏滑、电机模型偏理想。Ghost 洗出来的动作在这套仿真里完美。换一套接触参数，或上真机，脚又开始打滑。

ASAP 的结论更狠：敏捷动作（空翻落地）的瓶颈常常是 **仿真和真机动力学不一样**，不是参考漂不漂。他们用真机数据学一个「仿真里再补一截动作」，补的是仿真器。

所以 Ghost 现在的证书只保证：「在这份 MuJoCo 模型和这份力矩上限下，这段回放自洽。」换接触刚度就不算数。二区可以先做仿真器之间对打（同一段物理参考，换延迟/摩擦还能不能过质量门）。一区才需要真机。

## 7. 为什么「我们也能洗参考」不够发一区 / 二区

期刊/会议审的是 **新问题或新结构**，不是「在另一个机器人上复现」。

OmniTrack（2026 初，G1 真机）已经写完这个故事：

- 第一阶段开挂洗参考；
- 第二阶段闭着眼跟洗过的谱；
- 数据变多时，用生参考会越训越差，用洗过的参考仍然稳；
- 真机一小时、侧空翻、VR 遥操作。

Ghost 现在重叠的部分：开挂、不随机化物理、参考加噪声、放宽早停、失败多的片段多采样、真机力矩上限、把仿真回放存成新参考。换了 TK3 和 MuJoCo，质量门更认真，还允许手撑地。

审稿人会问的原句是：**拿掉 TK3 外壳，你的主张还剩哪一句我没在 OmniTrack 里读过？**

国内口头说的「一区/二区」大致是：

| 你听到的 | 实际更接近 | Ghost 优化后 |
|---|---|---|
| 小类一区 | Science Robotics | 需要全新能力和更大真机叙事，不建议当目标 |
| 很多学校算一区 | TRO / IJRR | 要在线因果滤镜 + 多接触 + 真机，还不能和 DSMS 撞「首次发现接触」 |
| 二区 | RA-L，或 ICRA/IROS | 最合适：残差怎么洗、硬门、接到 Tracking、消融表 |

「消融」就是同一套预算下关掉一个设计，看指标掉多少。没有这张表，编辑只能看到「我们调了奖励」。

## 8. 对照仓库：已经有的，和论文还缺的

**已经有（工程上是真的）：**

- 开挂观测、参考噪声、失败驱动采样；
- 鞋底凸包、橡胶接触；
- 允许脚和 TCP/手腕撑地；
- 回放质量门：FK 能否自洽、硬限位、力矩越限、穿地、悬空、根轨迹还在不在；
- 原型分支里的 `q_ref` 残差，以及「不要再精确奖励关节角，否则网络不敢改坏参考」。

**缺了就写不成上一篇说的二区故事：**

1. 用 `*_physical.npz` 去训 `TK3-Tracking`，证明洗过的谱比生谱更好学。
2. 训练中途就用质量门当失败，而不是只在最后打分。
3. `q0` 和 `q_ref` 两种动作都能跑，才能对比。原型把旧入口删了，投稿时必须留着。
4. 多段动作共用一个 Ghost，而不是一段动作一个网络（现在是单 clip 原型）。
5. 至少有起身/手撑/爬这类接触丰富的动作；只有舞，手撑接触是空头支票。

不需要为了论文去做的：把 Ghost 直接部署到真机（那是 Tracking 的工作）、上视觉、搬箱子。

## 9. 术语表（上一篇出现过的词）

| 词 | 人话 |
|---|---|
| 参考 / reference / motion clip | 希望机器人跟上的那串关节/身体轨迹，通常来自人 |
| 重定向 retarget | 把人的骨架套到机器人身上，多半只保证几何 |
| 穿地 / 浮空 | 参考脚在地里 / 该着地却没撑住 |
| PD | 用「差多少角、转多快」算力矩的底层跟踪器 |
| 策略 / policy | 神经网络，输出关节目标 |
| 特权 / privileged | 训练能看、真机没有的量（全局坐标、接触力） |
| 部分可观 | 真机只有编码器、IMU 这类 |
| 域随机化 DR | 训练时乱改摩擦、质量、延迟，逼策略别过拟合 |
| PMG / Ghost / Stage I | 开挂洗参考的那一阶段 |
| Stage II / Tracking / GMT | 闭着眼跟谱、准备上机的阶段 |
| rollout | 策略在仿真里整段演一遍并记下来 |
| 残差 | 输出「相对参考（或相对另一个策略）的修正」 |
| `q0` / `q_ref` | 默认站姿 / 当前帧参考角 |
| 硬门 vs 软惩罚 | 不许发生 vs 发生了扣分但还能刷别的分 |
| 接触模态 | 这一刻谁在撑地：左脚、右脚、手、膝…… |
| 因果 / 在线 | 只能用已经发生的过去和很短的未来，不能先看完整首歌 |
| 消融 | 关掉一个设计，看性能掉多少 |
| sim-to-real | 仿真里学会的，真机上还能用 |
| MPJPE | 平均每个关节离参考多远，毫米 |

## 10. 若你只记三句

1. **Ghost 不是会跳舞的机器人，是洗乐谱的人。** Tracking 才是歌手。乐谱洗完如果歌手不用，工程和论文都没有闭环。
2. **乐谱假（穿地、浮空、扭不动）时，歌手越认真越摔。** OmniTrack 已经把「先洗谱」写成主贡献；再写一遍换 TK3 不够。
3. **还能写的是洗的方法：** 只改错字（残差）而不是重写；洗的时候红灯不能闯（硬门）；手该不该撑地要能从脏动捕里看出来；直播不能先听完整首歌（因果）。每一条都要有对比实验，不能靠直觉。
